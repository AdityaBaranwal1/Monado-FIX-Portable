# Evidencia de validación — 2026-11-04

Esta revisión corresponde al árbol local XDE-Compilar-V5. No hay `.git`, `targets`, `generated` ni objetos del juego para enlazar `xcde.exe`. No se ejecutó gameplay, DLC ni un soak. No se publicó una release.

## Herramientas y resultados

- Python 3.14.7; Zig 0.13.0; SDK local con paquetes oficiales MSYS2. Versiones/URL/hashes de las descargas en `build/deps/validation-sdk.json`.
- **65 pruebas Python aprobadas**, cero omitidas, ejecutadas con `-W error::ResourceWarning` y capstone/lz4/unicorn disponibles. `VIOLATION: ... a.nsp` es la salida esperada de un fixture de rechazo del guard de paquetes; no es un archivo del juego incorporado.
- **17 módulos C/C++ compilados**: settings, framepace, party, bindings, filesystem, diagnósticos, objetos NVN, output scale y device/exec/shaders/textures/precompile/temporal/ImGui/menu/DLSS. Logs en `build/validation`.
- **Launcher independiente compilado y enlazado** con SDL3/Vulkan. Diagnóstico independiente compilado y enlazado. Esto no equivale al enlace del runtime completo con el juego.
- Última ejecución ampliada: cinco pruebas nativas aprobadas (`gpu_probe`, `movie_buf`, `translate_tex`, `tegra_block_height`, `fibers`); tres ejecuciones bloqueadas por Windows (`translate_ldc`, `tegra_copy`, `condvar`); cuatro omisiones explícitas por bloqueos observados (`port_core`, `settings_roundtrip`, `time_math`, `translate_xfb`). Los doce tests se compilaron en las iteraciones de comprobación.
- En compilaciones anteriores de esta misma sesión pasaron también `port_core`, `settings_roundtrip`, `time_math`, `translate_ldc` y `tegra_copy`. El nuevo caso de orden de espera por textura de ventana se compiló, pero no se ejecutó: Windows bloqueó ese nuevo binario de `port_core`. No se convierte esa compilación en un PASS de comportamiento.
- CI de componentes Windows añadida, sin ejecutar Actions en GitHub desde esta copia local. El guard sobre el índice Git tampoco puede ejecutarse aquí porque no hay índice; sus pruebas unitarias sí pasaron.

Las ejecuciones bloqueadas producen WinError 4551, «Una directiva de Control de aplicaciones bloqueó este archivo». No se modificó esa directiva ni se cambiaron nombres/rutas para eludirla. La última validación ampliada devuelve código no cero y conserva los diagnósticos: no es una suite completamente aprobada.

## GPU realmente observada

Salida del diagnóstico ejecutado antes de los bloqueos posteriores de recompilaciones:

```text
GPU 0: AMD Radeon (TM) Graphics
  uuid=00000000030000000000000000000000 vendor=1002 type=1 api=1.3.260
  usable=1: Vulkan 1.3 core
  driver=8388887 maxStorageBufferRange=4095 MiB; gameplay unverified
```

No se infiere un modelo comercial más preciso ni se presenta esto como prueba en Intel, NVIDIA o un equipo híbrido.

Los dos smoke se ejecutaron con éxito en una compilación anterior del diagnóstico, usando el mismo test procedural de clear/readback:

```text
smoke PASS: AMD Radeon (TM) Graphics, Vulkan 1.3 core, dynamic rendering + sync2 + timeline + 256 verified pixels
smoke PASS: AMD Radeon (TM) Graphics, Vulkan 1.2 KHR, dynamic rendering + sync2 + timeline + 256 verified pixels
```

Una recompilación posterior del diagnóstico quedó bloqueada por Windows; no se declara ejecutada esa recompilación. Los smoke prueban API/dispatch y una imagen procedural sin recursos del juego, no shaders traducidos ni estabilidad del port. El caso 1.2 usa un driver que ofrece 1.3 y las extensiones KHR; un dispositivo solo 1.2 continúa pendiente.
